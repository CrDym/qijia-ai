## 为什么做栖家

家电说明书、维修经验、出行准备、家人的病历和检查报告，常常散落在聊天记录、相册与文件夹里。栖家将这些信息收进一个可搜索、可持续积累的家庭资料库，在需要时找得到、看得懂，也能回到原始文件核对。

项目从小而实用的功能开始，按 **MVP → V1 → V2** 逐步迭代。当前为 V0，通过一个输入入口，把资料和要做的事整理到合适的位置，优先简单、模块化与长期可维护性。

## 核心特性

| 功能 | 当前能力 |
| --- | --- |
| 统一输入 | 首页粘贴文字、图片或拖入文件，AI 判断该整理资料、生成待办还是准备清单 |
| 确认卡片 | 一份内容可生成多条建议，分别调整、取消或确认保存；重试保存不会重复创建 |
| 今日生活 | 按北京时间展示逾期、今天、未来 7 天、未定日期、更晚安排与已完成事项 |
| 待办与清单 | 支持日期、备注、原始来源、逐项勾选、完成、重新打开、编辑和删除 |
| 家庭资料库 | 新增、编辑、分类、标签、摘要和来源记录；支持中文关键词搜索 |
| 文件导入 | 拖拽或选择 PDF、Word、TXT、Markdown，提取文字后可编辑 |
| 图片识别 | 上传或粘贴 JPG、PNG、WebP，自动识别并分类，原图与草稿一起核对 |
| 轻松收藏 | 粘贴原文或上传文件，AI 自动生成标题、摘要、分类和标签，确认一次即可保存 |
| AI 结果校验 | 严格 JSON Schema 输出与服务端校验；保留原文，支持修改结果 |
| AI 设置 | 配置官方或兼容服务的 API 地址、密钥与模型，保存立即生效，支持主动测试连接 |
| 家庭健康 | 建立成员档案，记录过敏史、既往病史，按成员与日期管理病历、报告和处方 |
| 原件保留 | 文件与资料一同保存，支持下载、替换和移除附件 |
| 街舞成长册 | 按日期记录课后展示与练习打卡，点击整个上传区或拖入多段视频，支持封面、播放与月份筛选；视频保存在本机，大小自动选择合适单位显示 |
| 本地存储 | SQLite 持久保存；无需单独运行数据库服务 |
| 响应式界面 | 支持桌面和手机，包含空状态、错误提示、未保存提醒和删除确认 |

**提供内容，自动整理，确认后保存。** 首页不必先选择工具或分类：发来缴费通知，可生成资料和待办；说“帮我列一份周末露营准备清单”，可生成待核对的准备建议。每张卡片单独确认，确认前不会写入数据库，也不会执行提醒或其他操作。没有 AI Key 或整理失败时，可以手动添加。资料库与家庭健康保留独立管理入口。

## 快速开始

需要 **Node.js 22.13+** 与 npm，建议使用兼容的 LTS 版本。

```bash
git clone git@github.com:CrDym/qijia-ai.git
cd qijia-ai
npm ci
cp .env.example .env.local
npm run dev
```

访问 [http://127.0.0.1:3000](http://127.0.0.1:3000)。如果尚未配置 GitHub SSH，也可以使用 HTTPS 克隆：

```bash
git clone https://github.com/CrDym/qijia-ai.git
```

初始资料库为空，数据库会按需创建到 `data/family.sqlite`。应用不会自动插入示例成员或健康资料。

### 配置 AI（可选）

进入页面导航中的 **AI 设置**（`/settings`），填写 API 地址（Base URL）、对应服务的 API Key 和模型，点击“保存配置”即可生效。地址留空使用环境变量，未配置时默认官方地址；已有密钥不回显，密钥留空表示保留。“测试连接”只发送固定文字，会产生少量 API 用量。测试验证文字与结构化输出，不代表图片识别效果。

也可在 `.env.local` 中填写，修改环境变量后重启服务：

```dotenv
OPENAI_API_KEY=你的_OpenAI_API_Key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1
DATABASE_PATH=./data/family.sqlite
```

| 环境变量 | 说明 |
| --- | --- |
| `OPENAI_API_KEY` | 可选，未在页面保存密钥时作为回退，仅在服务端读取 |
| `OPENAI_MODEL` | 默认 `gpt-4.1-mini`；需支持图片输入、Responses API 和结构化输出 |
| `OPENAI_BASE_URL` | 可选，默认 `https://api.openai.com/v1`；页面保存的地址优先 |
| `DATABASE_PATH` | 可选，默认 `./data/family.sqlite`；部署时应指向持久磁盘 |

请勿为密钥添加 `NEXT_PUBLIC_` 前缀，也不要提交 `.env.local`。完整配置示例见 [`.env.example`](.env.example)。

页面保存的配置优先于环境变量；“恢复环境配置”清除页面设置，重新使用环境变量。页面密钥保存在服务端 SQLite 中，当前未加密，数据库备份会包含密钥；不回传到页面，也不写入浏览器存储。当前没有登录保护，能访问平台的人也能修改设置。

兼容服务的地址示例：`https://api.example.com/v1`。使用服务商要求的路径前缀，不追加 `/responses` 或 `/chat/completions`。支持 HTTP(S) 地址（含本地服务），拒绝地址中的账号、密码、查询参数和片段。服务需支持 **Responses API 与严格结构化输出**，图片解析还需支持图片输入；仅兼容 Chat Completions 的服务暂不可用。切换地址时请使用对应服务的密钥，AI 请求内容会发送至该地址。

## 开始使用

- **整理日常**：首页（`/`）直接输入文字或上传文件 / 图片，停止输入后 AI 自动生成建议。核对内容、日期和不确定项，按需调整并分别确认保存。
- **查看安排**：首页“今天需要关注什么”展示事项；待办可完成或重新打开，清单支持逐项勾选，其他日期和已完成记录可展开查看。没有明确日期时留空，不默认今天。当前只有首页日期提示，不发送手机或邮件通知。
- **收藏资料**：点击“新增资料”，粘贴原文、选择或拖入文件，等待 AI 自动生成标题、摘要、分类和标签，核对后点击“确认保存”。无需选择分类；需要修改时展开“调整结果”。
- **识别图片**：上传、拖入或直接粘贴截图，AI 一次完成识别和整理；对照原图核对正文及不确定项，再确认保存。
- **自动识别健康资料**：资料库入口识别出病历、报告或处方后，自动归入健康档案并提取原文健康信息，只需额外确认所属成员；不会根据姓名猜测归属。
- **整理健康档案**：进入“家庭健康”，添加成员后点击“新增健康记录”；在健康表单顶部确认成员、类型、日期和机构，再上传病历、检查报告或处方。健康记录固定归入健康档案，可按成员、类型和关键词查找。

街舞成长册位于 `/dance`：选择课后展示或练习打卡，上传视频并确认日期即可；不调用 AI。支持 MP4，每段最大 1 GB，推荐 H.264 + AAC；MOV / HEVC 请先转换。视频独立存放在数据库同级的 `dance-videos/` 文件夹，备份时需一并复制。

家庭资料库位于 `/library`，家庭健康位于 `/health`，AI 设置位于 `/settings`。详细操作、文件格式、保存规则与备份方式见 [使用与部署指南](docs/guide.md)。

## 技术与结构

采用 Next.js App Router、TypeScript、Tailwind CSS、SQLite、OpenAI SDK 与 Zod。文件解析使用 `pdf-parse`、`mammoth` 和 `sharp`。

```text
src/
├── app/             # 页面与 API Route
├── components/      # 统一输入、事项卡片、资料库与健康档案界面
├── schemas/         # 输入、存储数据与 AI 输出的数据契约
├── services/
│   ├── ai/          # AI 业务入口与 Provider 适配
│   └── files/       # 文件校验、提取与上传请求解析
├── repositories/    # 资料、事项、成员与设置的持久化操作
└── lib/             # 数据库连接与通用请求处理
tests/               # 使用临时数据库和模拟 AI 的基础测试
docs/                # 使用、部署与维护文档
```

AI 调用集中在 service 层，页面不直接依赖供应商 SDK；数据访问集中在 repository 层。替换 AI Provider 或调整存储时，可以从对应模块开始。

### 开发与检查

```bash
npm run lint
npm run typecheck
npm test
```

测试覆盖日期归集、事项完成与重新打开、清单状态、确认重试幂等、资料与成员管理、附件持久化、图片校验、多卡片草稿、确认前不入库、健康成员确认和 AI 输出校验。测试不使用真实家庭资料，不调用付费 AI，也不代表对真实模型识别准确率的验证。

### 生产运行

```bash
npm run build
npm start
```

当前适合单台、有持久磁盘的 Node.js 服务，默认仅监听 `127.0.0.1`。部署与数据备份请参阅 [使用与部署指南](docs/guide.md)。

## 当前边界与数据说明

- 以下资料附件限制不适用于街舞视频；街舞视频保存规则见使用指南。
- 每条资料或事项保留一个原文件，最大 **10 MB**。PDF 最多 100 页，正文最多 20,000 字符。一份文件确认到多张卡片时分别保存副本，删除其中一条不会影响其他记录。
- 当前不包含主动推送、重复日程、日历同步或知识库问答。首页日期为北京时间的日粒度；原文具体时刻保留在备注，不触发定时通知。AI 生成的准备清单是建议，需要按实际情况调整。
- 图片支持静态 JPG/JPEG、PNG、WebP，最多 4,000 万像素。扫描 PDF 需先将所需页面转为图片再识别；HEIC、GIF、SVG 暂不支持。
- 当前没有登录、成员权限隔离或应用层数据加密。家庭成员是资料档案，不是独立账号；请勿将服务直接暴露到公网。
- 首页统一输入与“新增资料”会在提供内容后自动调用 AI，产生 API 用量：文字及文件提取的正文、或待识别图片会发送给当前配置的服务。手动表单只在点击 AI 按钮时发送；确认保存不会再次调用 AI。草稿仅在当前页面内存中，离开或刷新不会恢复。服务端设置 `store: false`，这不等同于供应商所有日志或留存政策的承诺。
- 健康 AI 仅整理原文，不进行诊断、不推荐或调整用药。请核对药名、剂量、数值与单位，诊疗以医生意见为准。
- 数据库、原件和备份应妥善保管。删除无法在应用内撤销，备份方式见使用指南。

## 迭代方向

当前已实现统一输入、今日事项、待办清单、资料管理、原件保存、图片识别与家庭健康档案。后续会根据实际使用反馈确定优先级，再评估主动提醒、更好的资料检索、多附件管理和知识库问答等方向；这些能力尚未实现，也不作为当前版本的承诺。
