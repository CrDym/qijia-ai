# 栖家使用与部署指南

[返回项目首页](../README.md)

项目采用 [MIT License](../LICENSE)。第三方依赖遵循各自的许可证。

家庭 AI 平台的 V0：通过一个输入入口，用 AI 整理资料、待办和生活清单；保存原文件，按成员管理家庭健康档案。

## 当前功能

- 首页统一输入文字、图片或文件，AI 生成可分别修改、取消和确认保存的资料、待办、清单卡片。
- 按北京时间归集首页事项，支持待办完成与重新打开、清单逐项勾选、编辑、来源查看和删除。
- 新增、查看、编辑和删除资料，包含标题、原文、摘要、分类、标签及来源。
- 点击或拖拽导入 PDF、Word（.docx）、TXT 和 Markdown，提取文字后可编辑；保存时保留可下载的原文件。
- 资料库新增入口支持上传或粘贴 JPG/JPEG、PNG、WebP 静态图片，一次 AI 请求识别文字、提炼摘要并自动分类，对照原图核对后确认保存。
- 五个分类：家庭事务、物品资料、实用知识、重要安排、健康档案。
- 家庭健康页面：成员档案、过敏史与既往病史、按成员与日期归档病历、检查报告、处方、体检及住院记录。支持搜索、类型筛选、编辑和下载原件。
- AI 整理健康记录：提取原文中的日期、医院、诊断/检查结论、处方和医嘱；不自动保存、不自动分配成员，不生成诊疗建议。
- 关键词搜索覆盖标题、正文、摘要、标签、来源和原文件名，支持中文；按最近更新时间排序。
- SQLite 持久保存，重启服务后数据仍在。
- 粘贴原文或上传文件后，AI 自动生成完整草稿，无需选择分类或逐项采用；确认一次即可保存。文字与文件提取的原文由服务端保留，不让模型重写。
- 桌面与手机布局、空状态、请求失败提示、未保存内容提醒、删除确认。

本版不包含扫描 PDF 自动识别、向量检索、知识库问答、登录、成员账号/权限、健康指标趋势、主动推送提醒、Agent 或多模型路由。家庭成员是本机档案，不是登录账号。

## 安装与启动

需要 **Node.js 22.13+**（推荐当前 Node 22 LTS 或更新 LTS）与 npm。SQLite 使用 Node 内置 `node:sqlite`，无需另外安装数据库或 ORM。文件解析使用 `pdf-parse` 和 `mammoth`，随 `npm ci` 安装；PDF 解析库的可选原生依赖通常使用预编译包。Node 22 可能打印 SQLite 实验性 API 提示，这是运行时提示，不代表启动失败。

```bash
npm ci
cp .env.example .env.local
npm run dev
```

打开 <http://127.0.0.1:3000>。首次保存位置默认是 `data/family.sqlite`，目录和表会在首次访问资料接口时创建。初始资料库为空，不自动插入示例或演示数据。

没有 AI Key 时，可以使用资料上传、手动录入、成员管理和搜索；AI 整理与图片解析按钮会提示尚未配置。

## 环境变量

在 `.env.local` 中配置，修改后重启服务：

| 变量             | 必填           | 说明                                                                     |
| ---------------- | -------------- | ------------------------------------------------------------------------ |
| `OPENAI_API_KEY` | 否 | 未在页面保存密钥时作为回退，仅服务端读取                                             |
| `OPENAI_MODEL`   | 否             | 默认 `gpt-4.1-mini`，需支持图片输入、Responses API 与 Structured Outputs |
| `OPENAI_BASE_URL` | 否 | 默认 `https://api.openai.com/v1`，页面保存的地址优先，可配置兼容服务 |
| `DATABASE_PATH`  | 否             | 默认 `./data/family.sqlite`，相对路径基于项目运行目录                    |

不要给密钥添加 `NEXT_PUBLIC_` 前缀。`.env.local`、数据库及其 WAL/SHM 文件已加入 Git 忽略规则。

### 页面配置 AI

资料库和家庭健康页面均提供“AI 设置”入口（`/settings`），桌面和手机都可访问。

1. 填写 API 地址（Base URL）、对应服务的 API Key 和模型，点击“保存配置”。下一次 AI 请求立即使用新配置，无需重启。资料整理、健康整理、图片解析和连接测试共用此配置；保存不会自动调用 AI。
2. 已有密钥不会回显，密钥输入框留空保留已有密钥；输入新值可替换。密钥、地址和模型分别优先使用页面保存值，否则读取环境变量；模型最终默认 `gpt-4.1-mini`，地址最终默认 `https://api.openai.com/v1`。环境密钥不会因页面保存而复制到数据库。地址输入框只显示页面保存值，旁边显示当前实际生效地址及来源；清空地址后保存会恢复地址回退规则，不清除密钥。填写完整官方地址可明确覆盖自定义环境地址。
3. 保存后点击“测试连接”。测试使用已生效的配置，仅发送固定测试文字，不发送家庭或健康资料；会产生少量 API 用量。通过测试表示文字和严格结构化输出可用，图片能力和识别准确率需实际核对。未保存修改时不可测试，避免误测旧配置。
4. “恢复环境配置”在确认后清除页面保存的地址、密钥和模型，不修改 `.env.local`。环境变量没有密钥时，AI 功能恢复未配置状态。此操作不删除家庭资料。

兼容服务地址示例：`https://api.example.com/proxy/v1`，本地服务可使用 `http://127.0.0.1:8080/v1`。保留服务商要求的完整路径前缀，服务端会追加 `/responses`；不要填写具体 `/responses` 或 `/chat/completions` 接口路径。地址会去除首尾空白及末尾斜杠，只接受 HTTP(S)，不接受内嵌账号、密码、查询参数、片段或空白字符；密钥应单独填写。公网服务建议使用 HTTPS。本地地址相对于应用服务器解析，而非访问页面的手机或电脑。

服务必须支持 Responses API 和严格 JSON Schema 结构化输出；图片功能额外要求图片输入。仅支持 Chat Completions 的服务暂不可用，应用不会自动切换协议。模型名称使用服务商实际提供的值，支持 `vendor/model` 形式。切换地址时请核对对应密钥；调用会将密钥和请求内容发送至配置的服务。

配置保存在服务端 SQLite 的 `ai_settings` 表中，已有数据库自动建表，无需清空。密钥仅在输入提交时传到本站服务端，之后不通过页面或查询接口回传，不进入浏览器持久存储。当前没有应用层加密和登录保护，请保护数据库及备份，不要将服务公开到公网；可访问应用的人也可以修改 AI 配置。恢复环境配置是逻辑删除，不保证从历史备份或磁盘中安全擦除旧密钥。

相关接口：`GET /api/settings/ai` 只返回公开配置状态，包括模型、实际地址、页面地址、地址来源、地址错误提示、密钥来源及是否有页面设置；`PUT` 保存配置，地址字段 `baseURL` 省略时保留原值，空字符串时清除地址覆盖；`DELETE` 恢复环境配置；`POST /api/settings/ai/test` 测试当前配置。写入和测试检查请求来源，所有配置响应禁止缓存，错误不暴露密钥或供应商原始响应。无效环境地址不会回显，也不会阻断手动管理资料；可在设置页面填写有效地址覆盖修复。

AI 使用 OpenAI Responses API 和严格 JSON Schema，再使用 Zod 校验返回值；同一份 Zod schema 同时定义数据类型和输出约束。服务端设置 45 秒超时、关闭自动重试；普通整理、健康整理、图片解析分别最多输出 1,600、5,000、8,000 token。处理拒答、限流、配置错误、截断及格式异常，各入口共享单进程并发保护。

资料库“新增资料”在粘贴原文或上传文件/图片后自动调用已配置的 AI 服务，产生 API 用量。文字输入停止约 1.2 秒后开始整理，中文输入法组词期间不触发；处理期间暂时锁定输入，失败不会循环自动重试。修改输入会使旧草稿失效并重新整理。手动表单与家庭健康专用表单仍只在点击 AI 按钮后调用；确认保存不会再次调用 AI。成员档案不会随 AI 请求发送，也不根据病历上的姓名自动归属成员。设置了 `store: false`，但这不等同于对供应商所有日志或留存政策的承诺。应用日志不打印正文、模型响应或密钥。

## 今日生活与统一输入

首页 `/` 是统一输入入口；家庭资料库移至 `/library`，家庭健康 `/health` 和 AI 设置 `/settings` 保持独立。

1. 粘贴文字、截图，或选择 / 拖入一个文件。一次只处理一份原文或一个文件；文字停止输入约 1.2 秒、文件选择后自动整理，输入法组词期间不触发。页面会提示发送给当前 AI 服务并产生用量。
2. AI 可生成一份资料、至多 8 个待办、至多 3 份清单，也可以说明需要补充内容。纯行动请求不必归档，同一份通知可以生成资料和待办。图片一次调用完成识别与整理，普通文件在本机提取文字后调用 AI。
3. 每张卡片独立调整、取消或“确认保存”。健康资料需要核对所属成员和原文信息。失败保留卡片，单条失败不影响已保存记录；每张卡片带稳定编号，重试只返回已创建的记录，不重复创建或覆盖它。修改已保存内容请在事项或资料详情中编辑。
4. 首页事项按“已逾期、今天、未来 7 天、未定日期、更晚的安排、已完成”展示。待办可完成与重新打开；清单可逐项勾选，也可整体完成或重新打开。编辑清单文字不会清除已有条目的勾选状态。每份清单最多 40 项，至少保留一项。
5. 处理完后点击“继续输入下一件事”。也可清空尚未保存的建议重新输入，页面会要求确认。没有 AI 配置或调用失败时，可在下方手动添加待办、清单或资料。

日期统一采用 **Asia/Shanghai（北京时间）**，按天归集，不受服务器时区影响。明确的“明天”等相对日期可按整理当天换算；只有月日、缺年份或其他不明确日期留空并提示核对，不默认今天。原文时刻保留在备注；当前不做定时推送、重复任务或日历同步。AI 返回符合格式的日期仍可能理解错误，请在保存前核对。

事项保留输入来源、原文 / 图片转录和原文件，支持查看来源与下载。每条记录至多一个附件；同一文件确认成多张卡片会保存独立副本，便于单独管理。删除事项会连同该副本删除，不影响其他卡片。当前事项附件不支持替换，可删除事项重新添加。原始数据不会在生成草稿阶段写入数据库。

首页不是知识库问答或自动执行 Agent。它不检索现有家庭资料，不会声称已发提醒或完成外部操作；查资料请进入资料库搜索。准备清单中的 AI 补充内容属于建议，不是预订记录、官方材料清单或医疗建议。

相关接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/home/prepare` | JSON `{content}` 或 multipart `file`，返回经过 schema 校验的草稿，不写入数据库 |
| `POST /api/home/confirm` | JSON `{id, kind, data}` 或 multipart `card` JSON + `file`，确认一张资料 / 事项卡片，稳定 UUID 防重复 |
| `GET /api/activities` | 查询已保存的待办与清单（包含来源文字，不包含附件二进制） |
| `PUT /api/activities/[id]` | 修改名称、日期、备注与条目，保留来源与附件，类型不可改变 |
| `PATCH /api/activities/[id]` | `{completed, itemId?}`，完成 / 重新打开整条事项或指定清单项 |
| `DELETE /api/activities/[id]` | 删除事项及其原文件 |
| `GET /api/activities/[id]/file` | 下载事项原文件 |

写入接口检查来源、输入 schema、请求大小和附件内容。AI 调用继续集中在 `services/ai/prepare-home.ts`，输出契约在 `schemas/home.ts`，事项存储在 `repositories/activities.ts`。启动时幂等创建 `activities` 与 `activity_attachments` 表，保留已有资料、成员和设置。文字整理最多输出 8,000 token，图片 12,000 token；失败不会自动循环重试。

## 资料库使用方式

1. 在资料库点击“新增资料”，粘贴原文或截图，或选择/拖入一份文件。一次只提供一份原文或一个文件；选择文件会替换当前待整理输入。
2. AI 自动识别内容、生成标题、摘要、标签并分类。无需选择分类，不受当前列表筛选类别影响。文字及 PDF/Word/TXT/Markdown 提取后只生成元信息；图片在一次请求中完成识别与整理。文件名保留为来源。
3. 查看结果。需要修改时展开“调整结果（可选）”，可修改标题、摘要、分类、标签、来源、正文及健康字段。图片展开原图与识别正文，并列出 AI 标记的不确定项。
4. 若识别为健康档案，额外选择所属家庭成员；成员不能为空，也不自动猜测。尚无成员时可在新页面建立后刷新成员列表，当前草稿保留。确认后点击“确认保存”，记录与原文件才一起入库，并返回全部资料列表方便查看。
5. 整理失败保留输入，可点击“重新整理”或“手动填写”；没有 AI 配置也可手动录入。切换手动表单会带入已有草稿、原文和选中的文件。扫描 PDF 暂不自动 OCR，应转成清晰图片或手动填写。取消未保存草稿不会留下资料或附件。
6. 已有记录的查看与编辑、家庭健康专用新增表单沿用原流程；通过搜索或侧边分类查找后，可编辑、下载原件或删除。

正文上限 20,000 字符，标题 100 字符，摘要 500 字符，来源 500 字符；最多 8 个标签，每个 20 字符，逗号分隔。自动整理支持非空短记录；旧手动表单中的 AI 整理仍至少需要 10 字符。草稿仅保存在当前页面内存，刷新不会恢复；关闭或刷新有未保存提醒。

自动整理接口为 `POST /api/documents/prepare`：JSON 只接受 `content`，或 multipart 只接受一个 `file`。返回经 schema 校验的完整草稿及不确定项，不调用资料保存接口、不写数据库、不分配成员。确认保存复用现有 `POST /api/documents`，再次校验成员、正文与附件。自动整理使用统一 AI 配置及全局并发保护，文字最多输出 5,000 token，图片最多 8,000 token。

## 家庭健康与图片使用方式

1. 进入“家庭健康”，添加成员。姓名/称呼必填，关系、出生日期、已知过敏史、既往病史和备注选填；空白表示未填写，不代表“无过敏/无病史”。
2. 选择成员并点击“新增健康记录”。健康表单顶部依次显示所属成员、记录类型、日期和就诊/检查机构，再上传病历照片或文件，也可以手动录入原文。多位成员时必须明确选择所属成员；健康记录的分类固定为“健康档案”，不能在表单中切换为普通资料分类。从资料库打开健康记录时也使用同一健康表单。
3. 图片导入后可预览原图。点击“AI 解析图片”，核对识别草稿和不确定项，再点击采用；已有正文会明确提示替换。未配置 AI 时可以手动填写正文并保存原图。
4. 点击“AI 整理健康记录”，核对原文提取出的日期、机构、诊断结论、处方和复诊安排，采用后仍需点击“保存健康记录”。原文缺失的信息留空；不完整日期不会补成年月日。原文健康信息在表单后半部分，可手动补充或修改。
5. 健康记录按记录日期从新到旧排列，日期未填的在末尾；支持按成员、类型和关键词筛选。编辑记录时可以改选成员，原文件默认保留。
6. 成员有健康记录时不能直接移除，需先转移或删除记录。删除记录会删除其原件；所有删除都需要确认，应用内无法撤销。

图片和健康 AI 输出仅是录入草稿，请重点核对药名、剂量、检查数值、单位和否定词。系统只整理原文，不诊断疾病、不推荐用药、不调整处方；医学影像不做诊断性解读。

## 文件导入说明

- 每条资料保留一个原文件，每个文件最大 **10 MB**。支持 `.jpg`、`.jpeg`、`.png`、`.webp`、`.pdf`、`.docx`、`.txt`、`.md`、`.markdown`；旧版 `.doc` 请先另存为 `.docx`。多张病历图片可分别建立记录；暂不支持一次上传多附件。
- 图片必须为静态图片，最多 4,000 万像素。`sharp` 校验真实格式并完整解码，拒绝损坏、伪装或超限图片。发送给 AI 前校正方向、缩放到最长边 2,400 像素并移除元数据；保存和下载的原件不修改，可能仍包含拍摄元数据。小字或长图识别不准时，请裁剪成清晰图片分开上传。暂不支持 HEIC、GIF、SVG，可先导出为 JPG/PNG。
- PDF 最多 100 页，提取正文最多 20,000 字符。超限会提示拆分，原有表单不会被覆盖。复杂表格、图片和版式不转换为正文，导入后需要核对；原文件完整保留供下载查看。
- 扫描版 PDF 暂不自动识别；未提取到文字时明确提示，可以手动填写正文并保留原文件，或将需要的页面导出为图片后使用 AI 解析。加密或损坏文件会提示错误。
- TXT/Markdown 支持 UTF-8 和带 BOM 的 UTF-16，其他编码请先转换。Word 会检查文件容器和展开大小。
- PDF/Word/文字提取与图片上传校验在应用服务器本地完成；资料库新增入口随后自动将提取文字或图片发送给 AI 整理。手动表单仅在点击 AI 按钮后发送。
- 导入阶段只在内存中提取，不持久保存；点击“保存资料”时原文件再次上传，与资料在同一个 SQLite 事务中保存。取消或提取失败不会留下附件记录。
- 编辑文字默认保留原文件；可重新选择替换，或点击“移除附件”后保存。移除附件保留正文；删除资料会同时删除原文件。
- 数据库自动新增 `attachments`、`family_members`、`health_records` 表，原有资料不变，不需要重建或清空数据库。附件使用 BLOB 保存，列表仅加载元数据，不读取文件内容。健康关联、正文与附件在同一事务内保存，成员不存在时整体回滚。

## 检查与生产运行

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

基础测试覆盖 SQLite 重开后的持久化、增删改查、中文及特殊字符搜索、分类计数、输入校验、请求体限制、跨来源写入拦截和 AI 错误处理。文件测试覆盖文字文件真实提取、静态图片真实解码、无效与超限文件、附件事务和旧数据库升级。健康测试覆盖成员隔离、日期排序、转移归属、删除保护、保存失败回滚和 AI 结构化结果/日期校验。测试使用临时数据库及模拟 AI 响应，不接触实际资料，不产生 AI 费用，也不代表已验证真实模型的识别准确率。

默认只监听 `127.0.0.1`，供本机使用。当前没有登录和访问控制，任何能访问服务的人都能读写资料并调用 AI；不要直接暴露到公网。如需可信家庭局域网访问，可运行 `npm run dev -- --hostname 0.0.0.0`，并自行限制网络访问范围。

健康档案和原件与其他资料一样保存在本机 SQLite 中，当前未实现应用层加密、成员间权限隔离或审计。请保护电脑与备份的访问权限。

生产部署适合一台有持久磁盘的 Node 服务器，使用 `npm run build` 和 `npm start`。设置 `DATABASE_PATH` 到持久目录。暂不适合无持久磁盘的 Serverless、多实例部署或多用户同时编辑；当前保存策略是后写覆盖。反向代理需正确转发 Host，并保持浏览器 Origin 与 Host 一致。

## 街舞成长册

进入导航的「街舞成长册」（`/dance`），点击「上传课后展示」或「上传练习打卡」。日期默认今天，可补录；选择或拖入一段或多段视频后保存。不需要填写标题、点评，也不会调用 AI。

上传框内整个虚线区域（包括「选择文件」文字）都可以点击，直接使用浏览器原生文件选择器；也可用 Tab 聚焦后按 Enter，或直接拖入视频。取消文件选择不会清空已选列表，再次选择同一文件也能正常更新。若内置浏览器未弹出系统窗口，可在系统浏览器打开同一地址或直接拖入文件。

- 按日期倒序展示，同一天、同类型自动归组；可筛选类型和月份，使用「补充视频」继续添加。
- 点击「批量管理」后勾选视频，也可「全选当前筛选」或清空选择。切换类型或月份会清空选择，避免误删隐藏的视频；「退出选择」不会删除任何记录。
- 「删除所选」会先显示数量、总大小和文件名摘要，确认后才逐段删除视频副本与封面。删除期间禁用选择和筛选；部分失败会停止并保留剩余选择，已成功删除的不会恢复。网络结果不确定时先刷新核对，再决定是否重试。删除无法在应用内撤销。
- 每段视频可修改日期和类型，修改后自动移动到对应分组。播放器支持全屏、拖动进度，旁边可选倍速。
- 支持非空 MP4，每段最大 **1 GB**。推荐 **H.264 视频 + AAC 音频**；扩展名为 MP4 不代表编码一定兼容。上传前在当前浏览器解码并生成封面，无法解码会提示转换。MOV / HEVC 请先用视频工具转换后导入；当前不提供自动转码。
- 多视频逐段保存，显示当前进度。失败时保留已成功的视频，待上传列表移除成功项。网络中断导致结果不确定时，先关闭上传框并刷新页面核对，避免直接重传。
- 视频复制到数据库同级的 `dance-videos/`，默认 `data/dance-videos/`；视频与 JPEG 封面不会写入数据库或 Git。导入前的原文件可以另行保留，移动原文件不影响应用中的副本。
- 删除前会确认，同时删除应用里的视频副本和封面，不影响导入前的原文件，不能在应用内撤销。页面底部显示已记录视频总大小（不含封面和其他资料）；单段视频与总大小按实际字节数自动使用 B、KB、MB 或 GB，避免小视频被显示成 0.00 GB。
- 上传中请保持页面打开。封面保存失败不影响已保存的视频播放，会提示部分封面失败。异常退出留下的 `.part` 为未完成上传，可在停止应用后删除。
- 此功能无需 AI Key；安装完成、应用启动后可离线使用。默认只监听本机，不提供手机直传或云同步。

## 数据备份

### 操作确认

视频（单段及批量）、待办、资料、健康记录、成员删除，以及放弃修改、替换输入、配置重置等操作使用统一页面内确认框。危险操作明确显示影响范围，默认聚焦「取消」；Tab 可切换按钮，Esc 取消并返回原控件，取消不会执行操作。表单内的确认会显示在原表单之上，保留输入。刷新、关闭浏览器标签页时的未保存提醒仍由浏览器提供，无法自定义其系统样式。

### 备份与恢复

最简单的备份方式：**先停止应用**，再复制整个 `data/` 目录到安全位置；使用自定义路径时备份数据库所在目录。恢复时停止应用并恢复对应目录。SQLite 开启 WAL 模式，不要在服务运行时只复制 `.sqlite` 主文件，否则可能遗漏尚在 WAL 中的写入。删除在应用内不可撤销，可以通过已有备份恢复。

资料、事项与健康附件保存在同一个 SQLite 数据库中，街舞视频和封面则在数据库同级的 `dance-videos/` 目录。必须同时备份数据库与该视频目录；自定义 `DATABASE_PATH` 时，两者也一起位于自定义数据库所在目录。以上备份会包含附件、孩子的视频和页面保存的 AI 密钥。请勿公开、提交或分享此备份。附件较多时，数据库和备份体积也会随之增大。
