# 栖家使用与部署指南

[返回项目首页](../README.md)

家庭 AI 平台的 V0：保存资料与原文件、用 AI 识别图片和整理内容、按成员管理家庭健康档案。

## 当前功能

- 新增、查看、编辑和删除资料，包含标题、原文、摘要、分类、标签及来源。
- 点击或拖拽导入 PDF、Word（.docx）、TXT 和 Markdown，提取文字后可编辑；保存时保留可下载的原文件。
- 上传 JPG/JPEG、PNG、WebP 静态图片，预览原图，主动点击 AI 解析后识别文字，核对草稿并采用。
- 五个分类：家庭事务、物品资料、实用知识、重要安排、健康档案。
- 家庭健康页面：成员档案、过敏史与既往病史、按成员与日期归档病历、检查报告、处方、体检及住院记录。支持搜索、类型筛选、编辑和下载原件。
- AI 整理健康记录：提取原文中的日期、医院、诊断/检查结论、处方和医嘱；不自动保存、不自动分配成员，不生成诊疗建议。
- 关键词搜索覆盖标题、正文、摘要、标签、来源和原文件名，支持中文；按最近更新时间排序。
- SQLite 持久保存，重启服务后数据仍在。
- AI 根据原文提出标题、摘要、分类和标签建议；用户采用后填入表单，再手动保存。AI 不修改原文。
- 桌面与手机布局、空状态、请求失败提示、未保存内容提醒、删除确认。

本版不包含扫描 PDF 自动识别、向量检索、知识库问答、登录、成员账号/权限、健康指标趋势、提醒、Agent 或多模型路由。家庭成员是本机档案，不是登录账号。

## 安装与启动

需要 **Node.js 22.13+**（推荐当前 Node 22 LTS 或更新 LTS）与 npm。SQLite 使用 Node 内置 `node:sqlite`，无需另外安装数据库或 ORM。文件解析使用 `pdf-parse` 和 `mammoth`，随 `npm ci` 安装；PDF 解析库的可选原生依赖通常使用预编译包。Node 22 可能打印 SQLite 实验性 API 提示，这是运行时提示，不代表启动失败。

```bash
npm ci
cp .env.example .env.local
npm run dev
```

打开 <http://127.0.0.1:3000>。首次保存位置默认是 `data/family.sqlite`，目录和表会在首次访问资料接口时创建。初始资料库为空，不自动插入示例或演示数据。

没有 AI Key 时，可以使用资料上传、手动录入、成员管理和搜索；AI 整理与图片解析按钮会提示尚未配置。

## 环境变量

在 `.env.local` 中配置，修改后重启服务：

| 变量             | 必填           | 说明                                                                     |
| ---------------- | -------------- | ------------------------------------------------------------------------ |
| `OPENAI_API_KEY` | 启用 AI 时必填 | OpenAI API Key，仅服务端读取                                             |
| `OPENAI_MODEL`   | 否             | 默认 `gpt-4.1-mini`，需支持图片输入、Responses API 与 Structured Outputs |
| `DATABASE_PATH`  | 否             | 默认 `./data/family.sqlite`，相对路径基于项目运行目录                    |

不要给密钥添加 `NEXT_PUBLIC_` 前缀。`.env.local`、数据库及其 WAL/SHM 文件已加入 Git 忽略规则。

AI 使用 OpenAI Responses API 和严格 JSON Schema，再使用 Zod 校验返回值；同一份 Zod schema 同时定义数据类型和输出约束。服务端设置 45 秒超时、关闭自动重试；普通整理、健康整理、图片解析分别最多输出 1,600、5,000、8,000 token。处理拒答、限流、配置错误、截断及格式异常，各入口共享单进程并发保护。

点击 AI 整理会将当前正文发送给 OpenAI，点击 AI 解析图片会将当前图片发送给 OpenAI；导入或保存不会自动调用 AI。成员档案不会随 AI 请求发送，也不根据病历上的姓名自动归属成员。设置了 `store: false`，但这不等同于对供应商所有日志或留存政策的承诺。应用日志不打印正文、模型响应或密钥。

## 使用方式

1. 点击“新增资料”，粘贴正文，或选择/拖入一份文件。导入会先提取文字，文件名作为默认标题和来源；已有正文时会先提示是否替换。
2. 手动填写标题，或点击“AI 整理”并检查建议。
3. 点击“采用建议”才会填入标题、摘要、分类和标签；原文和来源保留。
4. 确认后点击“保存资料”。
5. 通过搜索框或侧边分类查找，打开资料即可查看、编辑、下载原文件或删除。

正文上限 20,000 字符，标题 100 字符，摘要 500 字符，来源 500 字符；最多 8 个标签，每个 20 字符，逗号分隔。AI 整理至少需要 10 字符。

## 家庭健康与图片使用方式

1. 进入“家庭健康”，添加成员。姓名/称呼必填，关系、出生日期、已知过敏史、既往病史和备注选填；空白表示未填写，不代表“无过敏/无病史”。
2. 选择成员并点击“新增健康记录”，上传病历照片或文件，也可以手动录入。多位成员时必须明确选择所属成员。
3. 图片导入后可预览原图。点击“AI 解析图片”，核对识别草稿和不确定项，再点击采用；已有正文会明确提示替换。未配置 AI 时可以手动填写正文并保存原图。
4. 点击“AI 整理健康记录”，核对原文提取出的日期、机构、诊断结论、处方和复诊安排，采用后仍需点击保存。原文缺失的信息留空；不完整日期不会补成年月日。
5. 健康记录按记录日期从新到旧排列，日期未填的在末尾；支持按成员、类型和关键词筛选。编辑记录时可以改选成员，原文件默认保留。
6. 成员有健康记录时不能直接移除，需先转移或删除记录。删除记录会删除其原件；所有删除都需要确认，应用内无法撤销。

图片和健康 AI 输出仅是录入草稿，请重点核对药名、剂量、检查数值、单位和否定词。系统只整理原文，不诊断疾病、不推荐用药、不调整处方；医学影像不做诊断性解读。

## 文件导入说明

- 每条资料保留一个原文件，每个文件最大 **10 MB**。支持 `.jpg`、`.jpeg`、`.png`、`.webp`、`.pdf`、`.docx`、`.txt`、`.md`、`.markdown`；旧版 `.doc` 请先另存为 `.docx`。多张病历图片可分别建立记录；暂不支持一次上传多附件。
- 图片必须为静态图片，最多 4,000 万像素。`sharp` 校验真实格式并完整解码，拒绝损坏、伪装或超限图片。发送给 AI 前校正方向、缩放到最长边 2,400 像素并移除元数据；保存和下载的原件不修改，可能仍包含拍摄元数据。小字或长图识别不准时，请裁剪成清晰图片分开上传。暂不支持 HEIC、GIF、SVG，可先导出为 JPG/PNG。
- PDF 最多 100 页，提取正文最多 20,000 字符。超限会提示拆分，原有表单不会被覆盖。复杂表格、图片和版式不转换为正文，导入后需要核对；原文件完整保留供下载查看。
- 扫描版 PDF 暂不自动识别；未提取到文字时明确提示，可以手动填写正文并保留原文件，或将需要的页面导出为图片后使用 AI 解析。加密或损坏文件会提示错误。
- TXT/Markdown 支持 UTF-8 和带 BOM 的 UTF-16，其他编码请先转换。Word 会检查文件容器和展开大小。
- PDF/Word/文字提取与图片上传校验在应用服务器本地完成，不调用 AI。只有主动点击 AI 整理或解析图片才调用外部 AI 服务。
- 导入阶段只在内存中提取，不持久保存；点击“保存资料”时原文件再次上传，与资料在同一个 SQLite 事务中保存。取消或提取失败不会留下附件记录。
- 编辑文字默认保留原文件；可重新选择替换，或点击“移除附件”后保存。移除附件保留正文；删除资料会同时删除原文件。
- 数据库自动新增 `attachments`、`family_members`、`health_records` 表，原有资料不变，不需要重建或清空数据库。附件使用 BLOB 保存，列表仅加载元数据，不读取文件内容。健康关联、正文与附件在同一事务内保存，成员不存在时整体回滚。

## 检查与生产运行

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

基础测试覆盖 SQLite 重开后的持久化、增删改查、中文及特殊字符搜索、分类计数、输入校验、请求体限制、跨来源写入拦截和 AI 错误处理。文件测试覆盖文字文件真实提取、静态图片真实解码、无效与超限文件、附件事务和旧数据库升级。健康测试覆盖成员隔离、日期排序、转移归属、删除保护、保存失败回滚和 AI 结构化结果/日期校验。测试使用临时数据库及模拟 AI 响应，不接触实际资料，不产生 AI 费用，也不代表已验证真实模型的识别准确率。

默认只监听 `127.0.0.1`，供本机使用。当前没有登录和访问控制，任何能访问服务的人都能读写资料并调用 AI；不要直接暴露到公网。如需可信家庭局域网访问，可运行 `npm run dev -- --hostname 0.0.0.0`，并自行限制网络访问范围。

健康档案和原件与其他资料一样保存在本机 SQLite 中，当前未实现应用层加密、成员间权限隔离或审计。请保护电脑与备份的访问权限。

生产部署适合一台有持久磁盘的 Node 服务器，使用 `npm run build` 和 `npm start`。设置 `DATABASE_PATH` 到持久目录。暂不适合无持久磁盘的 Serverless、多实例部署或多用户同时编辑；当前保存策略是后写覆盖。反向代理需正确转发 Host，并保持浏览器 Origin 与 Host 一致。

## 数据备份

最简单的备份方式：**先停止应用**，再复制整个 `data/` 目录到安全位置；使用自定义路径时备份数据库所在目录。恢复时停止应用并恢复对应目录。SQLite 开启 WAL 模式，不要在服务运行时只复制 `.sqlite` 主文件，否则可能遗漏尚在 WAL 中的写入。删除在应用内不可撤销，可以通过已有备份恢复。

原文件保存在同一个 SQLite 数据库中，以上备份会包含附件，无需另外备份上传目录。附件较多时，数据库和备份体积也会随之增大。

## 代码结构

```text
src/
  app/
    api/documents/             # 列表、新增、单条读取/编辑/删除
    api/documents/[id]/file/   # 原文件下载
    api/files/extract/         # 文件上传与文字提取
    api/files/analyze/         # 主动调用 AI 解析新图片或已保存的原图
    api/health/members/        # 成员档案管理
    api/health/organize/       # 健康原文的结构化整理
    api/organize/              # AI 整理入口
    health/page.tsx            # 家庭健康入口
    page.tsx                  # 服务端页面，仅传递 AI 是否配置的布尔状态
    layout.tsx / globals.css
  components/
    knowledge-workspace.tsx    # 列表、分类、搜索和空状态
    document-dialog.tsx       # 详情、编辑与 AI 建议确认
    file-import.tsx           # 文件选择、拖拽与覆盖提醒
    image-analysis.tsx        # 原图预览、识别草稿与采用确认
    health-workspace.tsx      # 成员、健康概况与记录时间线
    member-dialog.tsx         # 成员档案编辑与删除保护
    health-record-fields.tsx  # 健康字段编辑和详情
    categories.ts / icon.tsx
  schemas/document.ts         # 文档与 AI 结果数据契约
  schemas/attachment.ts       # 文件类型、大小限制与元数据
  schemas/health.ts           # 成员、健康记录与健康 AI 输出契约
  schemas/image.ts            # 图片 AI 输出契约
  repositories/documents.ts   # SQLite 查询与持久化
  repositories/members.ts     # 成员持久化与删除约束
  lib/database.ts             # 数据库连接与首次建表
  lib/api.ts / client.ts      # 请求校验、错误响应与客户端请求
  services/ai/
    organize-document.ts     # 稳定的业务入口
    analyze-image.ts         # 图片输入预处理与识别
    organize-health.ts       # 健康资料整理
    run-exclusive.ts         # 各 AI 入口共享的单进程并发保护
    openai.ts                # 当前唯一的 Provider 适配
  services/files/
    extract-text.ts          # PDF/Word/文字提取
    validate-file.ts         # 文件内容与容器校验
    read-upload.ts           # 有界 multipart 解析与保存请求
tests/documents.test.ts
tests/files.test.ts
tests/health-images.test.ts
```

替换 AI Provider 时，保留三个 AI 业务入口的返回契约，替换 `services/ai/openai.ts` 的适配实现；图片预处理、业务提示词、前端和资料接口可保留。今后调整持久化只需从 repository 层开始。当前数据库变更仅为幂等建表；未来涉及已有列的数据变换时，再引入版本化迁移。
